## 1. 조사 목적 및 평가 기준

P2-STORE-01/02는 공급자 비종속 `PlaceSearchProvider` 인터페이스까지 구현된 상태로, 실데이터 공급자(어댑터)는 미선정·미연동이다. 본 문서의 목적은 국내 음식점·카페·베이커리 매장 데이터를 무료/저비용으로 확보하고 적법하게 저장·가공·활용할 수 있는지 판단할 **의사결정 자료**를 만드는 것.

평가 기준은 티켓 §4.2·4.3·5·6을 그대로 채택하며, 판정 원칙은 다음과 같다.

- 검색·조회 가능성(기술)과 데이터 이용 허가(권리)는 **별개 판정**.
- 약관·라이선스에서 명시적으로 확인되지 않은 권한은 **허용으로 추정하지 않는다**(3구분: 허용 확인 / 제한·금지 확인 / 미확인).
- 수치·조항은 확인일과 함께 기록하고, 실측하지 못한 정확도·커버리지·최신성은 미검증으로 표기.
- 확정 판단은 사용자 승인 사안; 본 문서는 후보 비교·근거·미확인 목록을 제공한다.

## 6. StoreDiscovery 인터페이스 적합성

P2-STORE-01 인터페이스(`PlaceSearchProvider`: `provider_id`/`contract_version`/`data_use`, `search(request)`) 기준 검토:

- 반경 검색: 카카오(문서상 좌표+반경) ○ / OSM Overpass △(질의 기반) / 포털·데이터셋형은 확인 필요.
- 키워드 전용 공급자: 현 인터페이스는 `center`+`radius_m`+`categories` 요청이므로 키워드 단독 검색은 어댑터 변환 필요(문의 파라미터화 여지 기록).
- 대량 다운로드 기반: 스트리밍/벌크 수집은 페이지형 `search`와 다른 형태 — 어댑터·저장 계층 설계 영향(후보 규정: `provider_place_refs`/관측 파이프라인).
- 공급자별 업종 매핑: 카카오 카테고리 그룹 코드(FD6/CE7 등)와 내부 업종 분류 연계 규칙 필요 — 업종 체계 미확정이므로 매핑표 확정 금지, 매핑은 공급자 어댑터/설정 계층 과제.
- 외부 ID 안정성: 카카오 `id` 등 문서 필드 존재; ID 안정성·재사용 정책은 미확인.
- 페이지 토큰·제한: 페이지 상한·토큰 방식 문서화(카카오); 공급자별 상이 → 예산/상한은 어댑터별 명시 설정.
- 호출 예산 관리: 엔진에 `page_budget`(명시 설정) 존재; **실제 연동 시 공급자별 유한 예산 필수**(요구사항으로 기록), 수치는 승인 전 임의 설정 금지.
- 데이터 사용권 표현: `DataUseRights` 선언값(3상태)은 자리 유지; 공급자별 권리 매핑·검증은 어댑터/설정·조사 필요.
- 관측 시각 vs 갱신 시각: 현재 후보는 제공자 보고 `collected_at`만 취급(엔진이 수집 시각 발명 안 함); 공급자 "데이터 갱신 시각"과 "관측/수집 시각" 구분은 어댑터·스키마 후속 설계(미확정).
- 인터페이스로 수용 불가한 요구사항: 벌크/파일 기반 공급자는 페이지 인터페이스 부정합 → 별도 수집 경로 설계 후보(미구현; 물리 스키마·승인 사안).

## 7. 비용 및 운영 위험

- 요금·쿼터 변동 위험: 공시 수치·요금은 변동 가능(카카오 문서 자체가 고지). 무료 할당 조건(계정·앱 단위) 확인 필요.
- 초과 비용·한도 초과 위험: 호출 예산·캐시·재시도 상한 필수; 429/제한 응답 처리 정책 필요.
- 약관·권리 변동 위험: 저장·재배포·AI·상업 조건은 약관/고지 변동 가능 → 주기 재검토·출처 기록.
- 데이터 현행성 위험: 폐업·이전·신규 반영은 공급자·데이터셋별 상이, 실측 미검증 → 최신성 정책·검증 절차 필요.
- 커버리지 편향: 상용/공공/개방형 각각 커버리지·분류체계 상이; 단일 공급자 의존 시 리스크(전략 C가 혼합 검토 대상이나 권리 관리 복잡).
- 운영·모니터링: 통계(쿼터 소모)·오류·제공자 변경 감시, 어댑터 회귀 테스트, 데이터 계보(출처·수집시각) 기록.
- 비용 외 비금전 위험: 키 관리(계정·비밀정보 취급), 이용조건 위반 시 서비스 중단·법적 리스크, AI 전송 제한 가능성(공급자별 확인 필요).
- 업무 경계: 이 티켓은 조사·평가까지만; 어댑터·키·약관 확정·연동은 승인 후 별도 티켓.

## 8. 데이터 모델 영향

rev 002(6테이블, 로컬 개발 DB) 기준. 신규 Alembic 리비전·DDL 없음. 논리 엔터티(미구현):

- `data_providers`/`data_usage_policies`: 공급자 메타·권리/정책 데이터의 기본 후보 엔터티(버전·의무·TTL). 권리 확정 전 물리화 금지(조사 결과 공급자별 상이).
- `provider_place_refs`: 외부 ID·내부 매장 연결·이력; 외부 ID 안정성 및 키워드(공급자별 ID 의미) 확인 전제.
- `place_observations`: 관측 데이터·TTL·만료; "수집/관측 시각"과 공급자 "갱신 시각" 구분 설계 필요.
- `store_facts`/`store_identity_evidence`: 권리 확보·판정 근거 계층; 본 조사만으로 확정 불가.
- 공통: 멱등성 키·계보(출처 URL·수집시각·계약/스키마 버전), 보존/삭제 정책 필드가 어댑터 도입 시 요구될 수 있음(설계 후보, 미확정).

## 9. 추천 후보와 추천 근거 (비확정 — 사용자 결정 사항)

- **단기 탐색 적합성**: 카카오맵 REST는 반경 검색·페이지네이션·카테고리 그룹·응답 필드가 문서로 확인 가능해 인터페이스 적합성 검토 착수가 가장 빠른 후보로 보인다(근거 S1~S3). 단 무료 쿼터 적용 조건(첫 활성화 앱)·요금·**데이터 이용 조건은 미확인**이므로 권리 검토가 선행 조건.
- **모집단의 공공데이터 축**(전략 B/C): 공공데이터포털 정책 문서로 저작물 권리 처리 프레임(제3자 권리·공공누리 유형)이 확인되어 조사 출발점은 명확; 구체 데이터셋(내용·주기·좌표·분류) 확인이 선행 과제.
- **개방형 데이터 축**(전략 D): ODbL 조건으로 복제·가공·상업 이용 경로가 문서상 명확하고, 국가 단위 추출(planet/Geofabrik 급) 경로 존재(별도 정책·실무 부담). 커버리지·업종 태깅·현행성 한계.
- **혼합형(C)**: 모집단 성격에 따라 매력적이나 계보별 권리·갱신·표기 관리가 최대 복잡도.
- **후순위 검토 메모**: 데이터 재배포·저장 조건이 엄격하거나 요금·의존성 부담이 큰 공급자는 요구사항 적합성 재평가 대상(추후 조사 후보; 이번 조사에서 확정 평가 안 함).
- B는 미확인 항목 해소 후 재평가 대상. 최종 선택·우선순위는 **사용자 승인 사안**이며 DECISIONS OPEN-001 유지.

## 10. 미확인 사항 및 사용자 승인 필요 사항

1. 공급자 약관·정책 원문 대조: 카카오(비즈니스/서비스 약관·운영정책) 저장·재표시·가공·결합·AI·상업·재배포 조건 — 본 세션은 개발자 문서까지 확인, 약관 본문 미열람.
2. 네이버 지역검색 전 항목(공식 문서 직접 확인 실패) — 재조사 필요.
3. 상권정보·지방행정 인허가 데이터셋별 항목·주기·좌표·분류·이용허락·입수 방식.
4. 각 공급자 실제 커버리지·정확도·현행성 — 실측 불가(금지·비실시) → 별도 검증 설계 필요.
5. 외부 식별자 안정성·재사용 정책, 중복·갱신 처리 규칙.
6. 호출 예산 수치·과금 조건(공고값 대조 후 우리 사용 조건 확정), 키 관리·비밀정보 방침.
7. 데이터 모델 후속 설계·물리 스키마/Alembic 리비전(별도 승인·티켓).
8. 공급자 연동 어댑터 구현·키 등록·실제 연동(별도 승인·티켓; 본 티켓 미실시).
9. 전략 A/B/C/D 선택 및 우선순위 = 사용자 결정.
10. 학과/법률 검토 필요성 판단(권리 해석·상업 조건).

## 11. 이번 티켓에서 하지 않은 것 (범위 준수)

실제 장소 API 호출·키 발급·계정 생성·크롤링·대량 다운로드·유료 서비스·임의 공급자 확정·미확인 권한 승인·신규 마이그레이션·Alembic 001/002 수정·기존 DB/백업 접촉·SourceDiscovery 구현·무관 리팩터링 — 모두 미수행. 실제 검색 정확도·커버리지·폐업 반영 실태는 실측하지 않아 미검증으로 표기.

## 12. 정정 이력 (2026-11-28, P2-STORE-04)

- 소상공인시장진흥공단 **상가(상권)정보 API**(공공데이터포털 15012005) 항목은 위 "미확인·직접 확인 실패"에서 **부분 확인**으로 정정: 공식 페이지 직접 조회로 형태·범위·제공출처 표기·업종 체계 개요·주요 필드·베이스 엔드포인트·문서화 오퍼레이션(지정/반경/사각형/다각형/행정동·건물·지번·상권·업종별·수정일 기준/변경요청/업종 코드 조회 등)·포털 메타데이터 조건(무료 표기, 심의 자동승인, 트래픽 항목)까지 확인(2026-11-28, https://www.data.go.kr/data/15012005/openapi.do). 단 세부 — **활용가이드 zip 내용·내부 버전·오류코드·세부 호출 제한·인증 절차·실체 갱신주기·검색 완전성·외부 ID 안정성·약관상 이용 조건은 여전히 미확인**(확인 필요, 추정 없음).
