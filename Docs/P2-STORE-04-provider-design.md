## 5. StoreDiscovery 공급자 어댑터 설계 (설계만, 구현 없음)

기준 인터페이스: `app/discovery/providers.py` (`provider_id`/`contract_version`/`data_use`, `search(request)`; `ProviderSearchRequest`: center·radius_m·categories·page_token; `ProviderSearchPage`: places·next_page_token) — P2-STORE-01 계약.

| 검토 항목 | 설계 초안 |
|---|---|
| 반경 800/1000 m 호환 | 인터페이스 radius_m(800/1000)을 그대로 매핑; 공급자 반경 상한·반경 의미(문서상 최대 2 km) 확인 절차 포함. 상한 초과 요청은 어댑터에서 거부·이슈 |
| 페이지 토큰 변환 | 공단 `pageNo`(1-based 문서)와 내부 불투명 `page_token` 상호 변환·검증은 어댑터 책임; 토큰값 형식 이상 → 구조화 오류. 엔진의 반복 토큰 방어(방문집합)와 공단 순차 페이지 특성 정합 |
| 응답 스키마 매핑 | 오퍼레이션별 상이 문서 스키마 → 오퍼레이션 단위 매핑·검증; 공통 필드(bizesId·상호·주소·좌표·업종코드·기준일) + 오퍼레이션 특이 필드 구분. 필드 누락/형상 이상 → 페이지 검증 실패 처리 |
| 좌표 변환·검증 | WGS84 문자열 파싱·범위 검증(위도/경도 한정; 문서 설명 라벨 혼선 관측 — 실측 파싱 규칙은 구현 시 검증); 변환 실패 → 기록·후보 미확정 |
| 업종 코드 매핑 | §4 매핑표에 따른 코드·라벨 매핑은 설정 계층(데이터 아님) — 임의 기본값 금지; 미지/복합 코드는 미분류로 기록 후 결정 필요 표시(공개 단정 금지) |
| 외부 장소 ID | `bizesId`는 **외부 참조로만**(내부 UUID 금지); 참조 무결성·이력·재사용 규칙은 §7·§8 설계 준수 |
| HTTP | 타임아웃·연결 오류 처리; 실시간 수집 금지 원칙과 무관한 서비스/배치 컨텍스트; 재시도는 멱등·예산 내 |
| 재시도·호출 예산 | **API 요청 횟수와 HTTP 재시도 횟수 분리 관리**(설계 요구); 둘 다 명시 설정·기록 대상. 실제 수치(호출·재시도·초당·동시성)는 조사·승인 전 기본값 설정 금지 |
| 오류 처리 | resultCode/resultMsg·HTTP 상태·타임아웃·스키마 위반을 구조화 오류로 정규화; **공급자 원본 메시지·URL·키 미노출** |
| 완전성·페이지 누락 | 응답 `pageNo`/`numOfRows`/`totalCount` 대조로 누락·중복·범위 이상 판정 보조; 불일치 시 해당분 재검증 절차·이슈(자동 보정 추정 금지) |
| 행기준 | 공단 스키마는 오퍼레이션별 상이 → 공통 최소 스키마 검증 + 오퍼레이션별 필수 필드 검증(고정 스크립트 아님) |

## 7. 매장 등록·갱신·중복 처리 정책 초안

- 최초 발견: 새 후보/레코드 생성 — 외부 ID 참조·수집 배치·좌표·업종·수집시각·출처 기록.
- 동일 외부 ID 재수집: 멱등 갱신 원칙(배치 재처리 중복 생성 방지) — 내용 변경 감지 시 필드 이력 기록, 증거 없는 덮어쓰기 금지.
- 상호명 변경: 공급자 값 기준 갱신 + 이력; 공단 정정요청 절차(문서상 존재) 활용 가능성·조건은 별도 확인.
- 주소·좌표 변경: 공급자 값 기준 갱신+이력; 좌표 검증 실패 시 플래그·미확정.
- 업종 변경: 코드 이력 관리; 매핑 재평가.
- 동일 상호의 서로 다른 지점: **별개 레코드**로 구분(자동 병합 금지; 지점·소재·참조로 구분 가능한 범위에서만).
- 공급자 검색 결과에서 사라짐: 미소출을 폐업으로 등치 금지; 변경 구분·기준일 등 신호와 운영 정책에 따름(정책 결정 필요).
- 외부 ID 변경·재생성: 공적 안내(번호 신규 방식·과거 연계 불가) 리스크 기록; 이력 연결 규칙 설계 필요.
- 일부 페이지 수집 실패: 엔진 동작(해당 공급자분 미지급/중단 + 구조화 오류, 기존분 유지) + 재시도 정책.
- 갱신 중 연결 장애: 재시도·오류 분류·부분성공; 배치 멱등성 유지.
- 공통: 자동 병합 금지(이름 유사만으로), 브랜드가·공식 할인 적용 등 데이터가 직접 증명하지 않는 속성 확정 금지.

## 8. API 호출 예산 설계

- **호출 예산 필수**: 실제 연동 시 공급자 호출은 유한·명시 예산 내(필드: API 페이지 요청 수). **수치 기본값 없음 — 조사·승인 전 설정 금지.**
- **이중계상 금지**: API 요청 수 vs HTTP 재시도 수 vs 기타 내부 왕복 분리 계측/상한(별도 설정).
- 서버/운영 컨텍스트 배치 전제; 사용자 실시간 조회 경로에서 공급자 호출 금지(제품 원칙).
- 기록: 요청/응답 메타(시각·페이지·결과 요약), 오류·재시도 사유, 비밀정보 비노출.
- 초과·429·오류 → 정지·분류·이슈, 재시도 정책 준수. 실제 한도·과금 미확정.

## 9. 서현역 최초 실증(POC) 계획 — 실제 연동 후 별도 수행

- 지역/반경/업종: 서현역, 800 m·1,000 m, 음식점·카페·베이커리 (업종 매핑 확정 후 적용).
- 수집 설계: 페이지 완전성(요청 페이지 vs `pageNo`/`numOfRows`/`totalCount` 대조), 외부 ID(`bizesId`) 중복률, 필수 필드 누락률, 좌표 유효성(WGS84 범위·파싱), 반복 수집 멱등성(동일 배치 재처리 시 중복 0 — 설계 기준 대비 실측), **실제 매장 존재 여부 표본 검증(현장/공식 근거)**.
- 산출: 지표 표·이상치 목록·조정 필요 사항; 데이터 계보(출처·수집시각·배치) 포함.
- 전제: 실제 키·연동·다운로드(본 티켓 미실시; 금지 항목 아님 — **승인 후 별도**)·좌표: **서현역 중심 좌표는 공식 근거 확보 전 확정하지 않음**.
- 본 티켓에서 실측·호출 없음.

## 10. 미확인 항목 및 사용자 결정 필요 사항

1. 공단 활용가이드(260805) 내용·버전, 오류코드, 세부 호출·동시성·재시도 규정.
2. 인증키 발급·승인 실질 절차(계정 유형·트래픽·증량).
3. 데이터 실제 갱신주기·기준일 관리(원천 국세청/카드사 기반 언급; 포털 "실시간"과 구분).
4. 공단 데이터 이용조건 최종 대조(저장·장기·가공·결합·표시·AI·상업·재배포·출처표시) — 미확인 다수, 외부 AI 기본 불허.
5. 지방세/인허가 데이터(후속 보완) — 데이터셋·형식·정책 미확인.
6. 업종 코드값·상권업종분류 개정/표준산업분류 연계표 버전 관리; 모호 사례(카페/제과 경계·복합) 규칙.
7. 물리 스키마 최종안·Alembic 003·ORM 구현(별도 승인·티켓); 테이블 우선순위는 §6 초안.
8. 갱신·병합·미소출·ID 변경 처리 규칙 확정(§7 초안 → 정책 확정).
9. 서현역 중심 좌표 공식 근거.
10. 지도 렌더링 공급자(OPEN-002) 등 잔여 결정.
