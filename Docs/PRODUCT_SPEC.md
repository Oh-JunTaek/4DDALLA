# 4 DDALLA — Product Specification

- Version: 1.0.0
- Status: BASELINED (design only; implementation unverified)
- Last updated: 2026-11-12 (DOC-001 보완 반영)
- Product: **4 DDALLA (사딸라)**

## 1. 제품 정의와 MVP

대한민국의 음식점·카페·베이커리가 제공하는 **실질적인 할인·혜택**을 공식 출처에서 찾아 구조화하고, 특정 매장에서 이용 가능한지 검증하여 지도·목록으로 보여주는 서비스다. 단순히 저렴한 매장을 할인 매장으로 취급하지 않는다.

- 최초 실증: 성남시 분당구 **서현역** 주변
- 반경: 기본 **800m**, 선택 **1km** (직선거리)
- 모바일 우선 반응형 웹. 네이티브 앱은 후속 검토.
- 서버가 미리 수집·검증한 데이터를 조회한다. 사용자 요청 중 실시간 수집/OCR/LLM 호출 금지.
- 일반 사용자는 로그인 없이 둘러보고 오류를 제보할 수 있다.

## 2. 확정 서비스 정책 P-001~P-019

| ID | 확정 규칙 |
|---|---|
| P-001 | **매장 적용 확인** 혜택과 **지점 적용 미확인** 혜택을 분리한다. 원문 해석 자체가 불확실한 데이터는 공개 확정하지 않고 운영자 검수한다. |
| P-002 | 정률·정액 할인, 특가, 1+1, 세트, 무료 증정, 쿠폰 등 실질 혜택을 포함한다. |
| P-003 | 정상가 미확인 시 검증된 행사가만 표시하며 할인율을 추정하지 않는다. |
| P-004 | 쿠폰·회원가입·앱·결제수단 등 조건부 행사도 포함하고 조건을 명확히 표기한다. |
| P-005 | 종료일 미확정 행사는 운영자 검수·승인 후 '기간 미정'으로 공개 가능하며 재검증한다. |
| P-006 | 기본 정렬은 거리순. |
| P-007 | 하나의 매장에서 여러 행사 진행 시 매장당 지도 핀 1개, 상세에 혜택을 묶어 표시한다. |
| P-008 | 종료 행사는 사용자 기본 목록에서 제외하고, 권한에 맞는 내부 이력만 유지한다. |
| P-009 | 비회원 제보 허용; 남용 방지·중복 방지 및 운영자 검수 필요. |
| P-010 | 기본은 **할인 매장만 보기**, 사용자가 **전체 음식점·카페·베이커리 보기**로 전환 가능. 장소 공급자의 조회·저장·표시 권한 준수. |
| P-011 | 미지원 지역은 안내와 지역 추가 요청 접수; 자동으로 무제한 신규 지역 수집을 시작하지 않는다. |
| P-012 | 매장 홈페이지·블로그·SNS 모두 공식 채널 발견 대상으로 삼는다. |
| P-013 | 공식 소유 관계 근거 부족 시 관리자 검수; AI의 높은 자신감만으로 승인 금지. |
| P-014 | 일반 이용자 후기·게시물은 후보 발견 단서일 뿐 혜택 확정의 직접 근거가 아니다. |
| P-015 | 허용된 자동 수집 경로가 없는 채널은 수집 중단하고 매장주 연동 후보로 관리한다. |
| P-016 | 객관적 검증을 통과한 행사는 자동 공개 가능; 불확실한 핵심 정보는 검수 대기. |
| P-017 | 일시적인 수집 실패 시 유효기간·최신성 정책 범위에서 검증된 기존 정보 유지, 경고 및 재검증. |
| P-018 | 초기 매장주 등록은 신청 접수 후 운영자 확인으로 처리한다. |
| P-019 | **모든 오류 발생 건을 빠짐없이 기록**하고 관리자 대시보드에서 집계; 심각한 오류만 별도 즉시 알림. |
| P-020 | 사용자의 위치 기능 사용은 강제하지 않는다; 지역 직접 선택을 지원한다. (2026-11-12 보완 추가) |

## 3. 사용자 공개 원칙

- 현재 유효한 **지점 적용 확인 행사**를 기본 목록과 할인 핀에 표시한다.
- 행사 자체는 검증됐지만 지점 적용이 미확인된 항목은 별도의 '적용 미확인' 목록/표식에 둔다.
- 예정 행사는 별도 필터 또는 섹션; 시작 전 혜택을 현재 이용 가능하다고 표현하지 않는다.
- 특정 요일·시간대·결제·쿠폰 조건을 모두 표시한다. 매장이 현재 영업 중이거나 사용자가 쿠폰을 보유했다고 단정하지 않는다.
- 폐업 확인 매장, 취소·종료 행사, 관리자 긴급 비공개 대상은 숨긴다.
- 조회 정보의 마지막 확인 시각 및 최신성 상태를 표시할 수 있어야 한다.
- 조사 결과 행사가 0건인 경우(조사 성공·대상 없음)와 수집·검증 실패로 확인되지 않은 경우를 구분한다('할인 없음'으로 뭉뚱그리지 않는다). (2026-11-12 보완 추가)

## 4. 제보 및 운영

제보 유형: 행사 종료/적용 거부, 가격·조건 오류, 매장 폐업·이전, 누락 매장·행사, 기타 데이터 오류. 제보 자체만으로 행사·매장을 자동 확정하거나 삭제하지 않는다. 관리자 결정에는 근거·시각·처리자·변경 전후 값을 기록한다.

## 5. MVP 제외 / 장기 확장

초기 제외: 자체 별점·후기·커뮤니티, 개인별 쿠폰 보유 판별, 매장주 셀프 관리 콘솔, 전국 동시 출시, 사용자 실시간 AI 분석, 네이티브 앱, 즐겨찾기·사용자 알림 등 미확정 편의 기능. 장기적으로 가격 대비 만족도 평가, 할인 후기, 커뮤니티, 제휴·광고, 매장주 공식 등록 채널을 검토한다. **광고는 검증된 할인과 구분·표기한다.** 서비스명·브랜드 아이덴티티·홍보물(상표·초상·영상 등)의 사용 권한은 별도 권리 검토 전까지 확정하지 않는다. (2026-11-12 보완 추가)

## 6. 미정 정책 수치

수집·재검증 간격, 종료일 미정 행사 재확인 상한, 오래된 정보의 경고/비공개 기준, 비회원 제보 제한량, 예정 행사 기본 표시 여부, 긴급 알림 채널은 POC 후 정한다. 개발 에이전트가 임의의 값을 영구 정책으로 확정하지 않는다.
